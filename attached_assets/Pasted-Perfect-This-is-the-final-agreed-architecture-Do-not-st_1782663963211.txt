==================================================
MASTERY COURSE MODEL
====================

This is NOT a Morning/Evening/Weekend batch system.

This is a Course Instance system.

For each grade, we can have a maximum of TWO running courses:

1. Current Admission Course
2. Previous Running Course

Example:

Grade 3

Course A
Students: 2,034–2,500
Admissions: Active
Status: Active

When we want to start a new intake:

Create:

Course B
Students: 0
Admissions: Closed
Status: Active

Admin clicks:

Activate Admissions

Result:

Course A
Admissions: Closed
Status: Active
Students continue normally.

Course B
Admissions: Active
Status: Active
All new admissions go here.

==================================================
VERY IMPORTANT RULE
===================

Existing students must NEVER move automatically.

Students already enrolled in Course A remain in Course A until completion.

Course A continues:

* Live Classes
* Recordings
* Homework
* Reports
* Mentor Communication
* Student Dashboard
* Progress Data
* Certificates (if applicable)

Nothing should break or move.

Only future admissions go into Course B.

==================================================
COURSE LIMIT
============

Maximum:
2 Active Mastery Courses per Grade.

Example:

Allowed:

Grade 3
├── Course A → Active
└── Course B → Active

Not Allowed:

Grade 3
├── Course A
├── Course B
└── Course C

To create Course C:

Course A must first become:

Status = Completed

Only then can another course instance be created.

Mastery Grade 3

==================================================
STUDENT ENROLLMENT
==================

Do NOT create student_enrollments table right now.

Reuse:

masteryStudentsTable.assignedCourseId

This becomes the source of truth.

One student can have only one active Mastery course.
