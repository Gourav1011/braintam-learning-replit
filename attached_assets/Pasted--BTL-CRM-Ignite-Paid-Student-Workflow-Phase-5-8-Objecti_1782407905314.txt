# BTL CRM – Ignite Paid Student Workflow (Phase 5–8)

## Objective

Implement the complete Ignite Paid Student lifecycle in BTL CRM.

Do not break existing functionality:

* Razorpay order creation
* Razorpay webhook verification
* Payment idempotency
* Existing Ignite dashboards
* Existing lead management

The recently created `ignite_paid_students` table will become the source of truth for paid Ignite students.

---

# Business Flow

Website Lead
↓
Student pays ₹39 / ₹99
↓
Razorpay Webhook
↓
Payment Captured
↓
Create/Update User
↓
accountType = demo_student
leadStage = Payment Completed
↓
Create ignite_paid_students record
assignmentStatus = unassigned
↓
Ignite → Paid Students → Unassigned
↓
Admin assigns IC/Mentor
↓
assignmentStatus = assigned
↓
Student appears in IC Dashboard
↓
IC contacts parent
↓
IC assigns Demo Batch
↓
assignmentStatus = batch_assigned
↓
Student attends demo
↓
assignmentStatus = demo_started
↓
Student completes demo
↓
assignmentStatus = demo_completed
↓
IC converts student to Mastery
↓
assignmentStatus = converted
OR
assignmentStatus = dropped

# Phase 5.3 – Assignment System

## Backend

Create endpoints:

GET /api/admin/ignite/paid-students/assignable-mentors

Return:

* id
* name
* email
* role
* active student count

POST /api/admin/ignite/paid-students/:id/assign

Request:

{
mentorId: number
}

Validation:

* Paid student exists
* Mentor exists
* Prevent duplicate assignment

Update:

assignedMentorId
assignedMentorName
assignedById
assignedAt
assignmentStatus = assigned

Preserve audit history.
