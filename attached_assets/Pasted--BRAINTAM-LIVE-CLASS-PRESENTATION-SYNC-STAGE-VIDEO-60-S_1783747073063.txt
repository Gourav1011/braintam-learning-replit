# FIX 7 — FIX THE 60-SECOND STAGE TIMER

The required limit is **60 seconds**, not 60 minutes.

Current bug:

```text id="0krm3a"
Timer reaches zero

→ Student is not fully removed

→ Existing stage state remains

→ Timer starts again

→ Same student appears again
```

There must be one authoritative stage timer on the server.

Do not run independent authoritative 60-second timers on every client.

Server stage state should include:

```ts id="3ekc90"
type StageSlot = {
  studentId:
    string;

  startedAt:
    number;

  expiresAt:
    number;

  status:
    "invited"
    | "accepted"
    | "live"
    | "expired";
};
```

When the student becomes live:

```ts id="js8qsp"
expiresAt =
  Date.now() +
  60_000;
```

The server owns expiration.

Clients only display:

```ts id="21q3f3"
Math.max(
  0,
  Math.ceil(
    (
      expiresAt -
      Date.now()
    ) /
    1000
  )
)
```

Do not restart the timer when:

* Component rerenders
* Socket reconnects
* Room state is received
* Track is subscribed
* Stage publisher state changes

At expiration, run one idempotent cleanup function.

Example:

```ts id="9mh52s"
async function expireStageSlot(
  sessionId:
    string,

  studentId:
    string
) {
  // Return immediately
  // if already expired
  // or removed.

  // Mark expired.

  // Remove slot from
  // active stage state.

  // Revoke LiveKit
  // publishing permission.

  // Emit stage removal
  // to the class.

  // Tell the student
  // to disable camera/mic.

  // Clear server timer.
}
```

Required expiration flow:

```text id="p0ptnp"
60 seconds reached

→ Server marks slot expired

→ Server removes active stage slot

→ Server revokes student publish permission

→ Server emits stage:expired or existing equivalent

→ Student disables camera

→ Student disables microphone

→ Teacher removes stage tile

→ Other students remove stage tile

→ Mentors remove stage tile

→ Student returns to viewer-only mode

→ Timer does not restart
```

The cleanup must be idempotent.

If the same expiration event runs twice, the second execution must do nothing.
