Enhance the EXISTING Workplace module only. Do not rebuild it and do not change the existing portal integration.

The goal is a **lightweight Zoho-style employee communication + work system**, not a full Zoho clone.

Keep the existing:

* Portal integration
* Authentication
* Roles/permissions
* Database
* Socket.IO
* Chat
* Groups
* Tasks
* Notifications

Only improve the missing functionality below.

# 1. REAL-TIME MESSAGE / TASK POPUP NOTIFICATIONS

When an employee receives:

* New chat message
* Group message
* @mention
* New task assignment
* Task reassignment
* Task status update
* Task completion

show a small **bottom-right toast notification** inside the existing Braintam portal.

Example:

```text
┌──────────────────────────────────┐
│ 💬 New message                   │
│ Rahul Sharma                     │
│ Please check the Grade 7 list.  │
│                         8:42 PM  │
└──────────────────────────────────┘
```

For task:

```text
┌──────────────────────────────────┐
│ ✅ New task assigned             │
│ Call pending parents             │
│ Assigned by: Academic Mentor    │
│ Due: Today                       │
└──────────────────────────────────┘
```

Requirements:

* Lightweight toast
* Auto-dismiss after a few seconds
* Click opens the relevant chat/task
* Do not create a heavy notification dashboard
* Do not show duplicate notifications for the same event
* Use existing Socket.IO infrastructure

If the user is already viewing that exact conversation, do not show an unnecessary popup for their own currently-open chat.

---

# 2. UNREAD COUNTS

The Workplace sidebar/menu must show unread counts.

Example:

```text
💬 Workplace   5
```

Inside Workplace:

```text
Chat        3
Tasks       2
Alerts      4
```

Individual conversations should also show unread counts.

Example:

```text
Rahul Sharma                 3
Academic Team                7
Ignite Mentors               2
```

When the employee opens the conversation and messages are actually viewed:

**Unread count becomes 0 and disappears.**

Do not clear unread counts merely because Workplace was opened.

---

# 3. MESSAGE ACTION MENU

Every message should have a small action menu.

For the user's own message:

```text
⋮
├── Reply
├── Edit
├── Delete
├── Copy
└── Mention
```

For another user's message:

```text
⋮
├── Reply
├── Copy
└── Mention
```

Only expose actions the user is authorized to perform.

Keep the menu compact.

---

# 4. EDIT MESSAGE + EDIT HISTORY

When a message is edited:

Show:

**Edited**

Example:

```text
Please call the parent today.   Edited
```

Everyone who can see the message can open:

**View edit history**

and see:

```text
Original:
Please call the parent tomorrow.

Edited:
Please call the parent today.

Edited by:
Rahul Sharma

Edited at:
2:35 PM
```

Important:

**Edit history must never be overwritten.**

Every edit creates a history record.

All authorized members of that conversation can see the edit history.

---

# 5. DELETE MESSAGE

Allow the sender to delete their own message.

Normal employee view:

```text
This message was deleted.
```

Admin/Super Admin view:

```text
Deleted message

Original:
Please call the parent today.

Deleted by:
Rahul Sharma

Deleted at:
2:42 PM
```

Admin should be able to see deleted-message content/history.

Normal users should NOT regain access to deleted content.

Do not physically destroy the audit/history record.

Use soft deletion.

---

# 6. MENTIONS

Typing:

```text
@
```

should open a small searchable employee/member dropdown.

Example:

```text
@Rahul Sharma
@Priya Singh
@Academic Mentor
```

Allow searching by name.

Selecting a person inserts the mention.

Mentioned users receive a notification.

For groups, only show members of that group unless the user has broader permission.

Keep this fast and lightweight.

---

Clicking a task should open a lightweight task detail panel.

# 13. EMPLOYEE RESIGNATION / INACTIVE USERS

This data must NOT disappear when an employee becomes:

* Inactive
* Resigned
* Deleted from active employee lists

Historical conversations and tasks must remain available to Admin/Super Admin according to existing permissions.

Example:

```text
Former Employee
Rahul Sharma
Status: Resigned

Past Conversations
Past Tasks
Completed Work
Task Remarks
Assignment History
```

Do not delete historical business records because the employee is no longer active.

For normal employees, follow existing permissions.

Admin/Super Admin should retain access to the historical record.

# 14. CONVERSATION → TASK CONNECTION

If a task was created from a conversation, keep the relationship.

Example:

```text
Conversation
     ↓
Message
     ↓
Task Assigned
     ↓
Task Completed
```

From the task, authorized users should be able to:

**View conversation**

and return to the exact relevant conversation/message when possible.

This gives management a history of:

**what was discussed → what work was assigned → what was done.**
