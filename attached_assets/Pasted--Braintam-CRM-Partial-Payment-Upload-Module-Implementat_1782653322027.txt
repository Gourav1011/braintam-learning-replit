# Duplicate Detection Engine

## Hard Duplicate

Check:
referenceNumber + paymentMode

If found:

* Block upload.
* Return:
  "This payment reference already exists."

---

## Soft Duplicate

Check:
studentId + amount within last 7 days

If found:

* Allow upload.
* Set:

isDuplicate = true
duplicateType = 'soft'
duplicateScore = 70

Store duplicatePaymentId.

# Overpayment Protection

Before upload:

remainingFee =
courseFee - approvedPayments

If uploaded amount > remainingFee:

* Show warning.
* Allow only Finance Admin override.

# Approval Workflow

Approval must run inside a single database transaction.

Pseudo Flow:

BEGIN TRANSACTION

Lock payment row

IF status != pending
RETURN error

Update payment status

Update student ledger

Generate receipt

Create notifications

Create audit logs

COMMIT

Rollback everything if any step fails.

Prevent double approvals from multiple admins.

# Mandatory Automated Test Cases

## Duplicate Tests

1. Upload same UTR twice → second upload blocked.
2. Upload same amount for same student within 7 days → warning badge only.

## Payment Workflow Tests

3. Upload payment → status pending.
4. Approve payment → ledger updated.
5. Reject payment → ledger unchanged.
6. Approve same payment twice → impossible.

## Permission Tests

7. Mentor cannot approve.
8. Mentor cannot delete.
9. Non-finance admin cannot override overpayment.

## Ledger Tests

10. Multiple installments calculate correctly.
11. Overpayment warning works.
12. Pending payments do not affect balances.

## Receipt Tests

13. Receipt numbers are unique.
14. Receipts generated only after approval.

## Concurrency Tests

15. Two admins click Approve simultaneously → only one succeeds.

## Audit Tests

16. Every action creates audit logs.
17. Logs cannot be modified.

## Archive Tests

18. Archived payments remain searchable.
19. Archived payments cannot be edited.
